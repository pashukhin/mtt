# t83 — Config schema reference (drift-guarded)

Ships an authoritative, exhaustive field reference for `.mtt/config.yaml` so a flow config is **authorable
from docs, not source** — plus a test that stops the reference from silently going stale.

## Why

Surfaced by the greenfield pilot: to author a mature config (`events`/`require`/`post`), the adopter agent
could not get the schema from FLOW_GUIDE/CLI_REFERENCE (a **tutorial**, not a field reference) and
reverse-engineered it from the Go struct tags in `internal/adapter/yaml/dto.go`. Reading source to write a
config is a documentation failure — and it blocks the next clean pilot, which asks an agent to author a
flow from scratch.

## What's in it

- **`CONFIG_REFERENCE.md` + `CONFIG_REFERENCE.ru.md`** — every `.mtt/config.yaml` field (and the
  `config.local.yaml` overlay keys `author`/`current`) as a table entry: **type · required/optional · its
  validity constraint · one-line semantics · a FLOW_GUIDE §-cross-ref**. Covers the whole surface —
  top-level keys, type/status/transition fields, the scalar-or-map command shape (`run`/`timeout`/
  `rollback`), the `events` store×kind×`post` shape, `require` (tighten-only + attribution order), and the
  edge-vs-event **placeholder** whitelists. required/optional is framed as a **validation** property (the
  DTO is decode-only, so `omitempty` is inert); the constraints an author actually needs — prefix charset,
  `kind` values + topology, edge-name uniqueness, default-must-be-`initial`, `ParseDuration` format,
  `version` — are stated at the field level.
- **`TestConfigReferenceCoversSchema`** — a drift guard: it extracts every distinct `yaml:"…"` tag from
  `dto.go` (all 33) and fails if any is not documented (as a backticked span) in `CONFIG_REFERENCE.md`. A
  new config DTO field with no doc entry → **red CI**. Guards the field *enumeration*; the validity
  *semantics* stay a review concern.

## Discoverability & sync

The new bilingual pair is registered in **both** agent rulebooks (`CLAUDE.md` and `AGENTS.md`); the README
Docs list, FLOW_GUIDE §1/§11, and the CLI_REFERENCE config-as-code note point into it (EN + RU); CHANGELOG
under `[Unreleased]`.

## Scope

Docs + one new test only. **No Go logic change** — no `cmd/`/`pkg/`/`internal` logic, `//go:embed` and
`BuiltinNames` untouched. `make check` green.

## Process

Spec → 2-round adversarial spec review (a missed `AGENTS.md` bilingual enumeration + the decode-only/validity
gap, both fixed) → human sign-off → plan (the reviewer *materialized* the test + doc and confirmed it passes)
→ human sign-off → TDD implementation → adversarial code review (APPROVE; 33/33 fields verified, EN⇄RU parity
confirmed). See `mtt show t83`.
