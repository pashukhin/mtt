## What

A release-gating **documentation audit**: reconcile the human-facing docs with the actually-shipped surface
(kill unshipped-as-present claims, internal contradictions, EN↔RU drift, stale versions) and add a
lightweight machine guard so these classes cannot silently drift again. Per the approved spec/plan
(`docs/superpowers/{specs,plans}/t42-user-docs-audit.md`; **1 spec round + 1 plan round + 1 impl round**,
each an adversarial fresh-subagent review). Evidence-based throughout — every finding re-verified against the
current binary/registry, not by eye. Blocks the pilot (t59) and public release (t60).

1. **Drift-guard test (`internal/cli/docs_guard_test.go`, in `make check`)** — the durable half. Three
   assertions, reusing `repoRoot()`/`NewRootCmd()`: (a) **registry ⊆ CLI_REFERENCE** — every live command has
   a `mtt <name>` heading (word-boundary prefix on the full-usage headings; handles `dep`/`ref`/`note`/`agent`
   group subcommands and the `tag`/`tags` collision); (b) **no phantom `mtt <verb>` tokens** in
   README/.ru + CLI_REFERENCE/.ru + CHANGELOG — each must be a registry command, a shipped-`default` status
   (sugar), a cobra built-in, or an entry in the maintained `knownVerbs()` allowlist (parked/planned/edge-sugar);
   **FLOW_GUIDE is excluded by design** (it teaches custom flows → arbitrary illustrative verbs); (c) **no
   hardcoded `x.y.z`** in a README status blockquote (the version is ldflags-injected). Written test-first: red
   on the pre-fix docs caught exactly the badge + the phantom `guide`; the doc fixes turn it green.

2. **README (EN+RU).** Version-agnostic, surface-accurate status line (dropped `0.8.98-dev` + the stale
   "Phases 1–3" list). `Key ideas` / `For agents` / `For humans` mark every unshipped feature (comment threads,
   text search, `mtt-ui`, external indexer) as **planned**, in sync with the top caveat — removing the
   caveat↔body contradiction; `refs` and knowledge storage (`mtt note`) shown as shipped. The parked `mtt start`
   is gone from the pitch/killer-feature prose (the shipped `default` template has no `start`; a gated status
   move `mtt status`/`mtt done` is representative).

3. **CHANGELOG.** Removed the never-existent `mtt guide` from the 0.9.0 entry; fixed the [Unreleased] c14
   template-name list `(coding, default, hierarchy)` → `(default)` (matching the binary and the same block's
   built-in-removal note). The released [0.9.0] "every command honors --json" summary is left as historical
   record (Keep-a-Changelog). Added an [Unreleased] `Fixed` entry documenting the audit + the guard.

4. **`--json` precision (`internal/cli/root.go`).** Root long-help "All commands support --json." → "Every
   command that emits output supports --json (the generated completion/help aside)" — matches reality
   (`completion`/`help` ignore the flag). CLI_REFERENCE already carried the exemption clause → verified, no
   change (a claim→verify no-op, not a blind edit).

5. **CLI_REFERENCE (EN+RU).** Status header reframed off a rotted "implemented today (through 008.98,
   `0.8.98-dev`)" enumeration (it had drifted — missing `note`/`ref`/`check`/`prime`/`self-update`/`agent`) to
   the per-command inline phase/session tags + `mtt --help`/`mtt version` (one source of truth, no parallel
   list to rot). Inline `*(phase 4)*` tags on the two `mtt comment` headings for parity (M4).

6. **DESIGN (EN+RU).** Fixed the broken hierarchy-template YAML example — **three** glued lines (two
   `}  - name:` type entries + a glued closing code-fence) so the block now parses (types epic/task/subtask)
   and renders, matching the already-correct RU mirror. `mtt start t17` → `mtt status t17 in_progress`.

7. **Scope discipline.** FLOW_GUIDE(+ru) verified (its `start` is an explicit "this repo's config" example,
   not the shipped default → no change); AGENTS.md/CLAUDE.md fact-checked on intersection only (English-only
   agent docs, clean). `internal/cli/CLAUDE.md` notes the new guard.

- **`make check` green before every commit** and at each task boundary; the guard's red→green happens within
  its task (observe red, apply the F1/F8 fixes, green) — never a red commit (the flow's clean-tree +
  make-check submit gate stays satisfied).
- **Driven on the real binary:** confirmed `mtt start t1` → `unknown command` while `mtt status t1 in_progress`
  / `mtt done t1` route on the shipped `default` template; `completion`/`help` ignore `--json` while
  `version`/`init` emit it; the phantom `guide` exists nowhere in the registry.
- **Guard proven to catch regressions** (in review): re-adding `0.8.98` to a README blockquote, a `` `mtt bogus` ``
  token, or an undocumented command each fires its assertion; allowlist has no dead entries; lint-clean.
- **Three adversarial fresh-subagent reviews**, each empirical (reviewers materialized and ran the guard,
  real `go test`/`golangci-lint`, parsed the YAML): spec review (guard-allowlist gap + missed findings folded
  in), plan review (cobra `help`/`completion` allowlist gap fixed before it could red the gate), impl review
  (caught the third glued fence — the YAML example was still broken; fixed and re-verified to parse).
