## What

The **`github-gated` flagship init template** — executable mtt gates on the **close of a GitHub issue**,
using only existing primitives (`mtt` self-calls + the t40 task-context env + `gh`), **no new Go**. This is
the last release-blocker for t60. Per the approved spec/plan
(`docs/superpowers/{specs,plans}/t76-github-gated-flow.md`; 1 spec round + 1 plan round + 1 impl round, each
an adversarial fresh-subagent review).

Re-scoped at brainstorm: **NOT** a GitHub TaskStore adapter. The useful middle of the external-tracker
spectrum is already reachable by composition, so this is **validate-then-build**:

1. **The model — two linked entities, not a status mirror.** A GitHub issue keeps its native `open⇄closed`
   model; a rich mtt task (a full gated flow in local YAML) *gates* it. The issue's **close is the task's
   terminal action**: `approve → done` runs `gh issue close --reason completed`, reachable only after the
   flow's gates pass. `start` creates the issue (`gh issue create`) and captures its URL back as a `url:` ref;
   a `sync` self-loop is a polled drift check.
2. **Written in t40 env-form.** The issue title rides the environment (`$MTT_TASK_TITLE`) as **data**, never
   interpolated into the command string; `{{.ID}}` is the only interpolation (shape-safe). So the injection
   boundary holds and no `mtt show` re-query is needed for the task's own fields.
3. **Packaged like the git-flow flagship** — a hosted, verbatim-installed example in `templates/`
   (`mtt init --template …/templates/github-gated.yaml`), guarded by `TestGitHubGatedStatesItsAssumptions`
   (states `gh`/`jq`/`--no-run`/`drift`/`author`/`bypass` — no silent traps).
4. **Enforcement honesty (in the docs).** mtt gates only `mtt`-mediated moves (choke point = `mtt <edge>`); a
   direct UI/`gh` move by **any** actor bypasses, and drift is **detect + complain**, polled and symmetric,
   never enforced. History with gate results lives in the mtt task (YAML) — no store-of-record problem.
5. **`mtt tt` decision: not built.** The dogfood proved the config-only pattern is ergonomic with t40, so no
   bespoke sugar was warranted — the template is the deliverable. The sole residual friction: t40's env does
   not carry a task's **refs**, so the issue-URL read stays an `mtt ref list --json` self-call (follow-up
   direction: t77's `--arg`).
6. **Docs (EN+RU).** FLOW_GUIDE §8b (the pattern + enforcement honesty + the two known interactions),
   DESIGN `Shipped (t76)`, CLI_REFERENCE + README sample lists, CHANGELOG. `templates/README.md` +
   `templates/CLAUDE.md`.

## Verification

- **Real out-of-tree dogfood over a scratch GitHub repo** (`pashukhin/mtt-t76-dogfood`, private, store
  in-tree like a real adopter — never this repo's live `.mtt/`). Load-bearing claims **proven end-to-end**:
  - **Happy path (t1 → issue #1):** `start` created issue #1 and captured `url:…/issues/1`; `sync` passed
    (OPEN); `approve` gated on OPEN then ran `gh issue close --reason completed` → issue #1 **CLOSED
    (COMPLETED)**, task **done**. The issue closed *because* the task passed its flow.
  - **Gate bites + drift (t2 → issue #2):** issue #2 closed **directly via `gh`** (bypass) → `sync`
    **detected drift** ("issue …#2 is CLOSED but task t2 is not done", gate exited 1, move blocked) → the
    `approve` gate **failed closed** ("already CLOSED (closed out of band?)"), the move was refused, the task
    **stayed in `review`**, and `gh issue close` never ran.
  - `gh issue create` emits exactly the URL on stdout → the capture is clean.
- **`make check` green before every commit** (template+test / dogfood / docs). `TestExamplesLoadAndValidate`
  now validates four hosted examples; `TestDocsNoPhantomCommands` kept honest (`tt` is not minted a command).
- **Adversarial reviews (fresh subagents, empirical):**
  - **plan_review** materialized the template and drove `mtt init --template` + the gates against the t40
    binary. It confirmed the mechanics (YAML valid; quoting injection-safe; jq `--arg` extractor; approve gate
    fails-closed; `ref add` fires `task.update`) and surfaced fixes, all verified against the binary and
    applied: the dogfood config path (`init` writes `<dir>/.mtt/config.yaml`), teardown scope + clone
    hygiene, and one **spec correction** — `require.who` gates **transitions**, not the inner `ref` self-calls,
    so there is **no** exit-2 attribution clunk (author-first is only needed to drive the flow edges).
    Owner signed off on the correction.
  - **impl_review** — this branch's final adversarial pass.

## Scope / deferred (deliberate)

- **True GitHub-as-store-of-record** (issues live only in GitHub; `mtt roadmap`/`list` read them live; the
  tracker may supply its own flow) — the external-store bet. **Deferred to t9** (amended 2026-07-27 to name it
  + the composition-root selection-seam prerequisite; overlaps t61). Not a silent drop.
- Projects v2 reflection, Trello, bidirectional reconcile, the universal-graph framing — later, demand-driven.
- Server-side enforcement (a GitHub Action rejecting an ungated transition) — a separate, heavier layer.
