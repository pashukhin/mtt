# Справочник конфига — `.mtt/config.yaml`

> English version: [CONFIG_REFERENCE.md](CONFIG_REFERENCE.md). Английский — источник истины; держите оба в синхроне.

Авторитетная схема конфига флоу проекта, поле за полем. Это **справочник** (для точечных look-up); чтобы
понять, **как авторить** флоу, читайте [FLOW_GUIDE.ru.md](FLOW_GUIDE.ru.md) — номера секций ниже ссылаются на него.

Конфиг флоу — это **доверенный код**: его gate/`post`/event-команды исполняются через `sh -c` с вашими
правами — запускайте или коммитьте только тот `.mtt/config.yaml`, которому доверяете, ровно как `Makefile`.
Живой конфиг — это overlay из двух файлов: закоммиченный `.mtt/config.yaml` плюс необязательный gitignored
`.mtt/config.local.yaml` (позднее выигрывает на уровне полей верхнего уровня). **`omitempty` в DTO инертен** —
конфиг только читается (decode-only), поэтому required/optional поля — это свойство *валидации* (ниже), а не
тег сериализации.

## Ключи верхнего уровня

| Поле | Тип | Обязательно? | Смысл / валидность | См. |
|---|---|---|---|---|
| `version` | int | обязательно | версия схемы; сейчас `1`. | §11 |
| `project` | map | обязательно | блок проекта; содержит `name`. | §1 |
| `project.name` | string | обязательно | отображаемое имя проекта. | §1 |
| `command_timeout` | duration | опц. (по умолч. `5m`) | бюджет на команду; формат Go `time.ParseDuration` (`5m`, `10m0s`); плохое значение падает при загрузке. | §4 |
| `author` | string | опц. | дефолтный acting-subject; обычно задаётся в gitignored `config.local.yaml`, а не в закоммиченном файле (см. Overlay). | §6 |
| `extract_hashtags` | bool | опц. (по умолч. `false`) | opt-in извлечение `#hashtags` из title/description задачи в теги. | — |
| `require` | map | опц. | политика обязательной атрибуции `{who, why}` (см. Require); **только-ужесточение**. | §6 |
| `events` | map | опц. | lifecycle-event пайплайны на не-flow мутациях (см. Events). | §5b |
| `types` | list | обязательно (≥1) | типы сущностей; каждый со своим флоу (см. Type). | §1, §3 |

## `types[]` — тип

| Поле | Тип | Обязательно? | Смысл / валидность | См. |
|---|---|---|---|---|
| `name` | string | обязательно | имя типа, уникальное среди типов. | §1 |
| `prefix` | string | обязательно | префикс id (YAML-адаптер минтит `<prefix><N>`); **только буквы** `[a-zA-Z]+`, **уникален** среди типов. | §3 |
| `parents` | list of string | обязательно (может быть `[]`) | имена родительских типов; `[]` = корневой тип; `[epic]` = размещается только под `epic`. | §3 |
| `default` | bool | опц. | пометьте **ровно один** тип `default: true` — используется `mtt add` без `--type`. | §3 |
| `description` | string | опц. | человекочитаемое описание, печатает `mtt types`. | — |
| `post_defaults` | list of command | опц. | финализирующие команды, добавляемые в начало `post:` каждого ребра этого типа (отказ на ребре — `inherit_post: false`). | §5 |
| `statuses` | list | обязательно | статусы (см. Status); нужно ≥1 `initial`, ≥1 `active`, ≥1 `terminal`. | §1 |
| `transitions` | list | обязательно | направленные рёбра (см. Transition). | §1 |

## `statuses[]` — статус

| Поле | Тип | Обязательно? | Смысл / валидность | См. |
|---|---|---|---|---|
| `name` | string | обязательно | имя статуса, уникальное внутри типа. | §1 |
| `kind` | enum | обязательно | одно из `initial` \| `active` \| `terminal`; должно **совпадать с топологией** (`initial` = нет входящих, `terminal` = нет исходящих, `active` = оба). | §3, §11 |
| `description` | string | опц. | печатают `mtt show`/`mtt types` (само-документирует следующий шаг). | — |
| `default` | bool | опц. | **не более одного** статуса `default`, и он **должен быть `initial`** (точка входа, когда у типа >1 initial). | §3 |

## `transitions[]` — переход (ребро)

| Поле | Тип | Обязательно? | Смысл / валидность | См. |
|---|---|---|---|---|
| `from` | string | обязательно | имя исходного статуса (должно резолвиться). | §1 |
| `to` | string | обязательно | имя целевого статуса (должно резолвиться). | §1 |
| `name` | string | опц. | глагол ребра для `mtt <name> <id>` / `mtt do`; **уникален на исходный статус** и **не пересекается с именами статусов**. | §3 |
| `description` | string | опц. | печатают у ребра `mtt show`/`mtt types`. | — |
| `commands` | list of command | опц. | **гейты** — исполняются по порядку; все должны выйти с 0, иначе move заблокирован (exit 3). | §4 |
| `current` | enum | опц. | `set` \| `clear` — двигает персональный указатель «текущая задача» (пусто = без изменений). | §6 |
| `require` | map | опц. | `{who, why}` на ребро; объединяется с глобальной политикой (только-ужесточение). | §6 |
| `post` | list of command | опц. | **финализирующие** команды *после* сохранения move; сбой сохраняет move (exit 5). | §5 |
| `inherit_post` | bool | опц. | pointer-семантика — отсутствие ≠ `false`; только явный `inherit_post: false` исключает ребро из `post_defaults` типа. | §5 |

## Команда (элементы `commands` / `post` / `post_defaults`)

Команда — это **скаляр-строка** (shell-команда через `sh -c`) **или** map:

| Поле | Тип | Обязательно? | Смысл / валидность | См. |
|---|---|---|---|---|
| `run` | string | обязательно (map-форма) | shell-команда. | §4 |
| `timeout` | duration | опц. | бюджет на команду, перекрывает `command_timeout`; формат Go `time.ParseDuration`. | §4 |
| `rollback` | command | опц. | компенсатор (скаляр или map), исполняется в обратном порядке, если *позднее* gate-команда падает; запрещён в любой `post`/event-поверхности. | §5 |

## `events` — lifecycle-пайплайны (только post)

`events:` вешает **только post** списки команд на не-flow мутации, per store × kind, срабатывает per entity,
только когда что-то реально сохранилось:

| Поле | Тип | Смысл | См. |
|---|---|---|---|
| `task` / `note` | map | store сущности, к которому применяются хуки. | §5b |
| `create` / `update` / `delete` | map | вид мутации; содержит `post`. | §5b |
| `post` | list of command | команды после сохранения этой мутации. | §5b |

## `require` — обязательная атрибуция

| Поле | Тип | Смысл | См. |
|---|---|---|---|
| `who` | bool | требовать acting subject до запуска гейта. | §6 |
| `why` | bool | требовать свободный текст-причину. | §6 |

**Только-ужесточение:** `config.local` и per-edge `require` могут *добавить* требование, но не ослабить
закоммиченное. Атрибуция резолвится по порядку: `--who`/`--by` > `MTT_BY` (env) > `author:` в `config.local.yaml`.

## `.mtt/config.local.yaml` — gitignored overlay

| Поле | Тип | Смысл |
|---|---|---|
| `author` | string | ваш персональный дефолтный acting-subject (источник истины для `by`). |
| `current` | string | персональный указатель id «текущей задачи» (управляется `current: set`/`clear`; руками не правится). |

## Плейсхолдеры

Раскрывается только фиксированный whitelist; любой другой `{{…}}` (например `{{.Title}}`) — ошибка шаблона,
никогда не интерполируется (граница безопасности — свободный текст едет через окружение, не через строку команды).

- **Ребро `commands`/`post`/`post_defaults`:** `{{.ID}}`, `{{.Type}}`, `{{.From}}`, `{{.To}}`.
- **`events.task.*`:** `{{.ID}}`, `{{.Type}}`, `{{.Event}}`.
- **`events.note.*`:** `{{.Slug}}`, `{{.Event}}`.

## Валидация конфига

`mtt add` и `mtt types` прогоняют структурную валидацию и отвергают сломанный флоу до рантайма (см.
[FLOW_GUIDE.ru.md §11](FLOW_GUIDE.ru.md)). *Ссылочная* целостность (висячие `depends_on`, циклы через
`mtt check`) — отдельная забота.
